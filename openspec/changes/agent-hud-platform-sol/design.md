## Context

See [proposal.md](proposal.md) for motivation and capability scope. `README.md`, `docs/architecture.md`, and the expanded `FEATURES.md` describe the intended product. Inspection found no application source, package manifest, tests, or existing capability specs. `openspec/config.yaml` selects `spec-driven` without additional project rules, and this change began with only its schema metadata.

This is an independent alternative authored proposal with the requested author profile `gpt-6.1-sol`, reasoning `max`. Its initial decisions came from local repository material; this revision also incorporates the locally reviewed Astra alternative as recorded in [peer-review.md](peer-review.md). No external sources were used. No private Codex table names, event names, Claude payload keys, or tested provider versions are asserted here. Compatibility is established through sanitized real fixtures and local CLI smoke checks during implementation; an unverified installed version must fall back rather than inventing a parser contract. Missing evidence for a required structured mode blocks completion of that mode.

The nine delta specs are the observable behavior contract. Runtime/library/platform selections below are proposed implementation decisions, not dependencies already present in the repository. This document plans implementation and does not authorize code changes, installation, commits, or publication.

## Goals / Non-Goals

**Goals:**

- Make each published revision safe to consume independently of the provider, with precise state, scope, ordering, and uncertainty semantics.
- Keep discovery and recovery inside adapters/source controllers and keep terminal output dependent only on normalized descriptors.
- Separate the lifetime of a launched agent and its I/O host from the replaceable HUD view.
- Deliver an offline generic vertical slice first, then verified provider integrations, with the same acceptance gates throughout.
- Make supported versions, fallback behavior, resource costs, and privacy decisions reviewable through fixtures and redacted inspection.

**Non-Goals:**

- Build native-TUI parity or a general agent frontend, synthesize approvals, scrape terminal pixels, or alter provider CLI source. Explicit Codex controlled mode includes only the minimal input/output/approval/cancel client described in decision 9.
- Promise richer Gemini/Aider telemetry, private-format stability, or cross-provider equivalence of effort, context, and quotas.
- Turn the internal adapter interface or local session endpoint into a public plugin SDK or shared multi-session state bus.
- Implement the roadmap's Later features listed in the proposal. Bounded operational buffers and optional short-lived retention do not constitute historical charting.

## Decisions

### 1. TypeScript runtime with enforced module boundaries

Choose TypeScript/ESM on Node.js 24+ with npm packaging and a lockfile. Initial supported platforms are Linux x86_64 and arm64; tmux 3.3+ is an optional backend dependency. Use Ajv for JSON Schema validation, a YAML parser for configuration, a pinned grapheme-aware display-width library with `Intl.Segmenter`, and Vitest for contract/replay tests. Use `node:sqlite` read-only connections inside a bounded worker for verified Codex database profiles and `node-pty` only where the session host actually requires a PTY. Native PTY artifacts must be built/tested for both supported architectures; no native provider database migration is permitted.

Proposed structure:

```text
src/contracts/     state, envelope, configuration schemas and field descriptors
src/core/          reducer, identity/scopes, clock, arbitration, source controller
src/privacy/       classification, projection, redaction, bounded retention
src/adapters/      generic, codex-observer, codex-app-server, claude, gemini, aider
src/usage/         local estimates and explicitly enabled command/HTTP providers
src/presentation/  sanitized field formatting, layout, themes, width handling
src/backends/      standalone, plain, tmux lifecycle
src/cli/           commands, session host, private ingress, wrapper integration
tests/fixtures/    synthetic contract traces and sanitized versioned provider samples
tests/integration/ PTY, tmux, process, transport and clean-install checks
examples/          generic snapshots/JSONL and shell/hook templates
```

Dependency direction is contracts → core/privacy → presentation → backends/CLI composition; adapters depend on contracts/core services, and only composition imports concrete adapters. Enforce this with static import checks, including a ban on common presentation importing provider modules. Plain ANSI output from normalized layout tokens is sufficient; a React-based TUI would add an unnecessary independent state lifecycle. Go/Rust could offer simpler standalone distribution, but TypeScript keeps JSON contracts and CLI adapter tooling together; the explicit runtime/native-module install gate pays for that choice.

### 2. Versioned values plus metadata, with explicit update coverage

Retain the architecture's readable common groups: `agent`, `cliVersion`, `sessionId`, `project`, `model`, `turn`, `context`, `usage`, `permissions`, and `activity`. Add `schemaVersion`, `revision`, `binding`, `sources`, `fieldMeta`, `capabilities`, `anomalies`, and `extensions`. `source` can summarize the primary source; it cannot replace per-field/group provenance when sources differ.

State schema v1 uses nullable typed values and a metadata map keyed by canonical field/group paths. Metadata includes scope type/key, source ID/epoch, observed wall timestamp if supplied, trusted receipt monotonic timestamp, last validation monotonic timestamp, quality, availability/reason, freshness, and privacy disclosure. Derived values record operand paths/scopes/revisions/watermarks and propagate the weakest relevant availability, freshness, and input quality while retaining derived origin. Public inspection projects internal times into displayed timestamps/ages. Model strings and provider effort labels remain literal, classified values. Extensions live under `extensions.<adapter-id>` and cannot redefine common paths.

The envelope includes schema version, message type, validated binding generation/session key, source ID/epoch, and source-local sequence or stable event ID. A handshake negotiates compatible major/minor schemas, mandatory features, field coverage, capabilities, and source identity before data. Unsupported mandatory features, unknown operations, and invalid known fields fail. Unknown optional telemetry keys/paths in a compatible minor version are size/depth checked, skipped, and never retained; unknown core configuration keys still fail as typos. Unknown extensions cannot gain common meanings or become visible without classified descriptors. This separates additive compatibility from schema mistakes rather than promising compatibility while rejecting every added field.

The controller stamps receipt/validation times and generation after checking the producer's session-scoped lease. A lease captures the generation at handshake; rollover retires it, so a delayed old connection cannot be stamped as current. Producer-supplied observation timestamps remain untrusted provenance, not freshness authority. A generic file begins with a handshake envelope and snapshot, or contains one documented bundle of those envelopes; JSONL begins with the handshake and then envelopes. Message semantics are:

| Message | Effect |
| --- | --- |
| `snapshot` | Declares authorized covered paths for one scope and replaces only that coverage; covered omissions become unknown; all other paths remain untouched. Complete keyed-collection snapshots can replace their declared collection coverage. |
| `patch` | Sets included paths; null or explicit clears invalidate; omissions remain unchanged. Tools, subagents, and usage records use scope-qualified ID upsert/remove operations, never positional edits. Only non-keyed arrays replace as ordinary values. |
| `invalidate` | Clears specified values or marks them unavailable/stale with a reason; does not silently erase independent scopes. |
| `source-health` | Updates only source health and applicable validation metadata; never invents new measurement observations. |
| `capabilities` | Replaces declared support; removed capabilities invalidate dependent values in the same revision. |

Validate recognized paths against descriptors and negotiated source coverage, reject prototype-polluting keys and conflicting replacement/upsert/remove operations, and require coherent groups such as context operands to be reduced together. Collection removal is telemetry removal, not cancellation or proof of completion. Reduce envelopes with an injected clock into immutable revisions; freeze them in tests/development. Revisions increase for the lifetime of the HUD instance, even across binding rollover. The view reads a single revision and never mutable adapter objects.

Independent dimensions prevent conflation: support is supported/unsupported; availability is known/unknown/unavailable with a reason; freshness is live/cached/stale; disclosure is visible/redacted; connection health is healthy/degraded/disconnected; quality is reported/derived/inferred/estimated with derivation inputs when applicable. Frozen is view metadata over a pinned revision. Presentation can show `estimated · stale · disconnected · frozen` without replacing one dimension with another. A single catch-all status or per-value wrapper was considered; the metadata map keeps the common architecture shape while preserving all dimensions.

### 3. Scope keys and privacy at the ingestion boundary

Scope types are HUD instance, launch, process, worktree, account, session, and turn. Provider thread, fork, subagent, and parent identities are distinct relations, not interchangeable IDs. Process keys include PID plus start identity; worktree keys use canonical repository/worktree evidence; account keys use opaque per-host hashes of verified provider identifiers. Unknown account keys are never equivalent to one another for cache retention. Launch keys may correlate a process-only session but are not presented as provider session IDs.

Classify and apply privacy policy before normalized values enter state, logs, history, or cache. Raw parsing buffers exist only transiently within ingestion limits. Adapters may privately hold file handles, exact paths, and identity evidence needed for observation; those values cannot be exposed through unprojected diagnostics. Source labels and scope keys in public state use opaque identifiers or approved reduced forms. Unknown extensions default to hidden; prompt/response bodies are discarded unless their individual display controls explicitly permit them.

Defaults hide content, goals/titles/summaries, usernames, account identifiers, tool arguments, and credentials; paths show at most an approved project leaf, never an absolute home path. Repository/branch and quota/cost disclosure have independent controls; the privacy profile hides them. Explicit content display and explicit content retention are separate settings. Authentication tokens are never displayable through normal field controls. Retention defaults to off; an enabled policy is capped at 512 projected records, 4 MiB, and ten minutes, whichever is reached first. Deduplication/high-water bookkeeping is separate from content retention and contains no raw text.

One projection service serves rendering, inspection, exports, diagnostics, and storage. A stricter reload purges forbidden queued/retained values and HUD-owned logs, including rotated files, reprojects the frozen revision, and swaps configuration/projection together. Serialize policy activation with sink-write admission: each chunk/export checks the current privacy revision immediately before writing; queued old projections are canceled or rebuilt, and incomplete HUD-owned export staging is discarded. Bytes already admitted before activation and completed user-owned exports cannot be recalled; explain that boundary when explicitly exporting, without claiming physical secure erasure. A relaxation admits only newly observed data. Output-only masking and unversioned asynchronous writers were rejected because logs, frozen snapshots, and prepared exports would otherwise leak the same data.

Use owner-only runtime directories (0700) and private endpoints/descriptors/log/cache/export/backup files (0600), validate ownership/type, and create/replace without following unsafe symlinks or clobbering unrelated files. Keep caches memory-only by default; an explicitly enabled durable quota cache needs a stable verified account key and finite TTL. Permission checks/nonces prevent accidental cross-session routing within the same user's trust domain; they do not sandbox same-user code. Parser/worker isolation is likewise a resource boundary.

### 4. Binding generations and a recoverable source controller

Binding evidence includes explicit adapter/session selection, launch ID, child process/start identity, terminal backend identity, cwd/worktree, and parent lineage when available. Explicit selections outrank hints but are still checked. Never use newest-file sorting to resolve concurrent sessions. If candidates remain ambiguous, publish discovering/unresolved with redacted candidate evidence; noninteractive `attach` exits 4 before creating a backend. Interactive selection occurs only in the HUD's own input surface.

Lifecycle transitions are: discovering → binding after one validated candidate; binding → synchronized after a coherent baseline; synchronized → degraded when a required source fails but verified fallback exists; degraded/disconnected → binding during recovery; any active state → stopped on observation shutdown. Disconnected means no valid active source for the bound session, not a reason to drift to another process. A process-only fallback cannot invent turn state. Source failures and backend failures are separately represented.

Advance binding generation on establishment, detach/rebind, or an identity-affecting selector change, even for the same verified session. Detaching only a view does not rebind its surviving host. Advance source epoch for transport reconnect, rotation, or sequence restart within an otherwise unchanged binding. Every read, database job, poll, event, and producer lease captures generation/epoch; retired subscriptions/leases are canceled and checked before reduction, including health/counter updates. Rollover stages handshake, identity, capabilities, and a bounded initial baseline, then commits one new-generation revision clearing old session/turn-scoped facts. Retain independent worktree/account data only on matching verified keys with prior ages. Same-session accounting continuity may resume only after validated checkpoints. If identity is confirmed but the baseline fails, publish a degraded new binding with unknown session fields; never relabel old values. A fork/subagent is not an automatic root replacement.

Periodic reconciliation verifies the intended current root and all selected source identities even if old files remain readable. Database rows may establish a successor only when corroborated by the selected launch/process/pane/session lineage. Broad cwd matching alone remains ambiguous. A permanent filename attachment would be simpler but cannot satisfy concurrent-session and rollover behavior.

### 5. Per-field authority, event order, and accounting checkpoints

Profiles declare source authority by coherent group. In controlled mode, verified app-server events are primary. In observer mode, verified model-selection log events can outrank durable model snapshots; durable cumulative token snapshots can be accounting baselines; verified rollout events carry turn/context evidence. Hooks outrank process inference for fields they actually validate. Agent-reported current cwd outranks process cwd for that field; launch cwd remains its own field. Account quota queries outrank only correctly keyed quota caches, not unrelated usage fields.

Order within a source by epoch/sequence/event identity. For durable reads, capture read-start monotonic time and cursor/checkpoint; reject replacement of a field changed by event evidence after that read began. A later read can supersede an event only when the profile can establish that its snapshot includes the event's watermark/current state. Prefer healthy fresh authority; use a lower-ranked fresh source when the higher-ranked one is unavailable. Without compatible ordering evidence, expose contradictory measurements and retain the last trustworthy selection rather than comparing provider wall clocks or blindly applying last arrival.

Accounting keys include session/turn scope, source/metric, counter epoch, and category inclusion. Cumulative observations replace their authoritative baseline; deltas are applied once above its checkpoint. Do not sum cumulative observations, inclusive cache categories, overlapping quota windows, or parent and child usage. Parent/subagent data carries `includesChildren` as true/false/unknown; complete aggregation requires compatible disjoint scopes, explicit exclusion, and complete child coverage. Partial subtotals are labeled partial. A lower cumulative number needs explicit reset evidence; otherwise mark it contradictory and reconcile. Compaction updates context independently of lifetime accounting; compaction alone is not reset proof and its count is reported rather than inferred from token decreases.

Keep at most 4096 dedup IDs alongside source high-water marks. Old events at/below a retained sequence watermark remain rejected after ID eviction. If replay identity across source epochs cannot be established, stop delta accumulation and request a covered cumulative baseline; an adapter offering only uncheckpointed deltas remains uncertain after recovery. Overflow, sequence gaps, and rejected accounting records invalidate affected totals until resynchronization. Last-write-wins and naive sums were rejected because neither can prove complete usage.

### 6. Monotonic validation and bounded work

Inject monotonic and wall clocks. Elapsed turn duration is measured from local monotonic evidence; observed start timestamps remain separately reported when known. Do not fabricate a precise elapsed duration for a previously running turn when only an uncorroborated wall timestamp exists. Quota reset countdown uses the absolute wall deadline, remains nonnegative for display, and becomes “pending refresh” at expiry. Suspend detection uses event-loop gaps and wall/monotonic divergence; invalidate validation leases and reconcile before returning live.

Stable model/project/idle facts renew a validation lease only through a profile-specific check of source continuity and identity, including consuming available records. A verified gap-free heartbeat/catch-up or authoritative snapshot can validate the fields it covers; unsupported heartbeat assumptions and process liveness alone cannot renew model/context/quota or prove turn completion. Renewal preserves the original observation time. Quotas expire independently of process health. Publish cached immediately after a failed applicable validation, stale after its threshold, and independently disconnected connection health after confirmed source/session loss. Quiet idle streams do not alone prove disconnection.

| Default limit/cadence | Choice and behavior |
| --- | --- |
| File debounce | 50 ms; configured default window remains 25–100 ms. |
| Poll fallback / root reconciliation | 2 s / 5 s; validated ranges 500 ms–30 s / 1–60 s, one active operation/source, jitter at most 10%. |
| Stable-source validation lease | 15 s, renewed only by applicable successful validation. |
| Quota observation TTL | 5 min or earlier provider expiry; health checks cannot refresh quota observations. |
| Rendering | Dirty-state batching, at most 20 interactive frames/s or 10 plain revision groups/s; elapsed/countdown display at 1 Hz. |
| Input queue | Global maximum 1024 records and 8 MiB bytes, checked before enqueue. |
| Record / depth | 256 KiB / 32 levels, including generic/hook input. |
| Parser work | 10 ms cooperative slices; 100 ms record watchdog, including database/parser workers. |
| Source/retry bounds | At most 8 active source connections; retry backoff 1–30 s, at most 5 attempts/cycle and one active attempt/source; stop cancels retries. |
| Local observers / database locks | 2 s total, 256 KiB combined output; SQLite busy wait at most 100 ms/attempt within that total; kill only owned observer process groups. |
| Replay slice / staging / total recovery | At most 4 MiB or 250 ms/slice; 8 MiB staging plus normal queue limits; stop at 64 MiB read or 30 s total recovery, whichever first. |
| External subprocess/HTTP | 5 s timeout, 1 MiB total output/response, at most 2 concurrent usage queries, 60 s minimum per-provider refresh. |
| Operational logs | 1 MiB ring and at most 2000 projected entries, whichever is reached first; no automatic upload. |

Pre-scan record length/depth before parsing; move blocking database/parsing operations into workers with cancellation and generation checks. JSONL retains a bounded partial tail until newline; truncation/rotation starts a new epoch and verified baseline. On overflow, stop the affected stream, publish uncertainty/drop counts, and request resynchronization. Replay into bounded staging with scope/checkpoint progress, schedule slices fairly across sources, and publish complete accounting only after a validated baseline plus contiguous buffered events. Exceeding the total recovery ceiling leaves that source degraded with unknown/cached totals and a checkpoint remedy; do not automatically restart the same full scan. A new checkpoint/source or explicit retry can begin a new bounded cycle. Coalescing replaces display frames only, never accounting evidence. Unlimited retries/replay and unqualified convergence deadlines were rejected because they sacrifice responsiveness or fabricate completeness.

### 7. Common telemetry descriptors and computation

Descriptors publish units, allowed scopes, quality, privacy category, display priority, and capability dependencies. Context values use context-scope token occupancy; derive percent as `100 * used / capacity` only for compatible scope with positive capacity, and remaining only when operands are consistent. Preserve raw overflow evidence and emit an anomaly rather than clamping a meter. Token totals are separate turn/session measurements. Output speed is tokens/s only from token deltas, otherwise explicitly characters/s or bytes/s; use a documented rolling five-second interval with at least one second of valid observations.

Git uses bounded `git` argument-array subprocesses with an explicit cwd and local porcelain/worktree/reference inspection. No fetch is performed. Record branch versus detached head, status counts, optional local ahead/behind, and the worktree key; refresh on verified directory/worktree changes and a bounded dirty-state poll. Repository root and product project root need not be identical. Permission/sandbox/collaboration descriptors carry an observation label.

Activity uses scope-qualified tool-call/subagent IDs and keyed updates. Completion without a verified start has unknown duration; synthetic IDs remain inferred and cannot join uncertain cross-source calls. Configured/loaded/active extension states, completed records, and typed anomalies are bounded; anomalies carry scope/revision and safe codes, never raw source bodies. Plans/goals/titles/summaries have independent privacy classes, so permitted completion counts can survive withheld item text. Summary display alone permits only the current summary; separate retention consent governs history. Summaries are optional adapter input, never HUD-issued summarization requests. Terminal text scraping and session-token-based context estimates were rejected because they cannot establish these meanings.

### 8. Verified internal adapter profiles

| Adapter/mode | Planned acquisition and support boundary |
| --- | --- |
| Generic | The public v1 handshake/envelope schemas over JSON bundle, JSONL stdin/pipe, watched file, or private ingress; strongest reference implementation and offline demo. |
| Codex native observer | Versioned, read-only rollout/state/log readers plus process/pane evidence. Rollout supplies durable supported facts; verified state profiles detect matching new roots; verified logs can advance model state. Failed/untested profiles downgrade independently. |
| Codex app-server | Explicit literal server command; persistent minimal built-in control client owns input/output/approval/cancel and verified transport. A separate read-only event projection feeds normalized telemetry. |
| Claude | Explicitly installed status-line/command shim; producer sends a sparse payload with inherited launch correlation and current generation handshake. Hook PID is never the session key. Existing status-line output is preserved by an inspectable chaining template. |
| Gemini / Aider | Executable/version discovery and process/project/Git profiles; richer capabilities remain unsupported until verified local samples and conformance evidence exist. |

Each profile manifest records adapter/schema version, verified CLI range, source format/version probes, identity checks, capabilities, sanitized real fixture provenance, smoke procedure/results, and recovery behavior. Tiers are `structured-verified`, `hook-verified`, `fallback-verified`, `unverified-version`, and `unavailable`, per mode/source with source kind recorded independently. Version matching is insufficient when format probes fail. Parsing stays in the adapter; read-only database workers return bounded rows and never copy whole databases into diagnostics. Similar keys do not justify guessing. Synthetic fixtures verify the HUD contract, not provider compatibility. Full completion needs a real locally verified CLI version for Codex observer, Codex controlled, and Claude hooks; unavailable samples or executables are explicit blockers for those tasks. Unsupported fields within a verified mode still remain unavailable; Gemini/Aider promise only verified fallback coverage.

Alternative universal filesystem crawling would risk both identity mistakes and private data retention. A plugin loader is deferred; internal adapters can demonstrate extensibility without executing arbitrary third-party code.

### 9. Session host, ingress, and controlled transport

Separate the replaceable view from a small session host. `attach` starts an observation host without owning the agent; it stops its watchers after its last view closes. `run` starts a host that owns the launch, process group/PTY when needed, ingress, source controller, and privacy-safe state. That host outlives HUD view loss and waits for child termination; the wrapper reports the child's exact exit/signal result. A separate HUD pane/terminal consumes projected revisions. Closing it is a view event, not a child-stop event.

Native run preserves argv/cwd/existing environment and adds `OPENAGENTHUD_HUD_ID`, a fresh `OPENAGENTHUD_LAUNCH_ID`, `OPENAGENTHUD_PARENT_LAUNCH_ID` when applicable, and `OPENAGENTHUD_INGRESS_DESCRIPTOR`. The descriptor holds the private endpoint/nonce; no authentication token is placed in inherited environment or argv. `OPENAGENTHUD_SESSION_ID` is provided only when genuinely known. Nested wrappers preserve parent launch lineage, create a new descriptor, and reject conflicting active target descriptors; inherited environment alone never establishes subagent or provider-session identity. Producers authenticate and receive a session-scoped generation/source lease; old leases require renegotiation after rollover. Per-view controls and telemetry are distinct message types with no unrestricted agent-command path.

Use Unix-domain sockets under a 0700 owner directory in the user runtime directory, falling back to a freshly created private temporary directory. Socket, registry, and producer descriptor are 0600 with symlink-safe ownership/type checks. Keep authentication nonce only in its private descriptor; registry/view diagnostics contain opaque identities and privacy-safe state. Accept one active producer per source ID with per-connection and global limits; reject collisions rather than merging streams. Remove stale resources only after matching owner process-start evidence. This remains private single-launch IPC, not the Later public state bus or a same-user security sandbox.

Controlled invocation is explicit: `run --adapter codex --integration app-server -- <server-executable> <verified-app-server-arguments...>`. Users supply the literal server command, including its locally verified mode arguments; wrappers never convert a native CLI command to app-server. The host starts a persistent minimal line-oriented control client for verified session/turn input, sanitized response output, explicit known approvals, cancellation, and connection status on the original client input surface. Protocol pipes are owned by that client; use a PTY only if a locally verified mode requires it. Native-TUI parity, general command automation, and an external compatible-client ecosystem are excluded. This replaces the prior external-client prerequisite with a bounded deliverable inside the change.

Only deliberate focused-client input creates control requests. Key pending requests by verified session, binding/control generation, and protocol request ID; show safe request details and accept an explicit allow/deny only for a currently verified supported request. Unknown approval types remain pending with an actionable error. Agent output/telemetry can never parse into a decision. A read-only projection mirrors verified events into the adapter; common HUD modules cannot import the action sender. The control client's intentional conversation surface is distinct from HUD telemetry retention; its logs, caches, errors, and mirrored observations follow the same privacy rules and terminal sanitization. Unsupported transport negotiation fails closed rather than forwarding unknown action types.

Renderer loss preserves the client, transport, and pending requests. On transport reconnect, reconcile session identity, request status, and delivery acknowledgments before accepting decisions. Never replay input/approval/cancel with unknown delivery outcome unless the verified protocol establishes idempotency and confirms that exact request/session; otherwise show uncertainty for deliberate user resolution. Retired/reused request IDs cannot receive a stale response. Client-owner loss leaves requests unanswered and follows verified disconnect semantics, exposing interrupted/disconnected state without inferred success. A local fixture server plus the real-version smoke gate verifies these responsibilities; no private method names or native-TUI client support are assumed.

The session host owns the PTY master/relay until the child ends. If the HUD view dies, agent/client I/O continues through the host and original agent terminal. Signal ownership is explicit: attach stop affects observation only; run's intended child interrupt is forwarded once by the host or delivered directly to the foreground child process group, never both. An explicit child stop is separate from pane/display teardown. Losing the host itself remains a recoverable process/terminal failure to diagnose; losing an entire tmux server cannot guarantee survival of tmux-hosted agent processes. Those limitations cannot be mislabeled as HUD-only failure.

A single process owning both HUD rendering and agent PTY was rejected because closing the display could otherwise close the PTY and send the agent a hangup. The host is a lifetime supervisor, not the deferred separately sandboxed adapter helper.

### 10. Deterministic presentation and backend ownership

Convert one privacy-projected revision into sanitized field tokens, then layout, then backend output. Sanitizing removes/escapes telemetry ESC/CSI/OSC/DCS, C0/C1 controls, unexpected line breaks, and unsafe directional overrides. Only trusted renderer styling can emit terminal controls. Use grapheme segmentation and display-width calculation before truncation; permit a documented width override for terminals whose emoji conventions differ.

Reserve a compact freshness/anomaly indicator, then preserve agent, model, turn, project, branch in that priority order before context, usage, timing, and activity. Configured field order controls placement; omission priority remains deterministic. At extreme widths retain an ASCII freshness/anomaly marker and explicit truncation. Default compact height is two lines; expanded is four; full is eight; presentation is two with stricter privacy; height remains independently selectable from one through ten. Monochrome/high-contrast/ASCII/reduced-motion are orthogonal switches, and the Claude-like palette maps semantic roles rather than provider identity. Plain output contains sanitized append-only lines; `TERM=dumb` forces it regardless of selected interactive profile.

Standalone `attach` can own its terminal alternate screen. Standalone `run` can use a distinct `--hud-tty` or explicit plain `--output <path>` while the agent keeps its original terminal. If neither is selected outside tmux, create the launch registry and print a safe copyable `openagenthud attach --launch-id <opaque-id>` instruction before spawning; a second terminal owns the HUD, with no ongoing rendering in agent stdio. Reject same-TTY interactive conflicts before launch. Inside tmux, use a detached split adjacent to the verified agent target and preserve focus. Non-TTY HUD output defaults to plain meaningful revision groups with bounded coalescing. Keyboard shortcuts apply only on the HUD's focused surface.

Tmux identity records server/socket identity and process start, session/pane IDs, and an `@openagenthud_owner` tag with the HUD UUID. Commands use argument arrays and explicit socket/target. Verify the tag and server identity before every cleanup; remove only HUD panes, never agent panes or a server/session containing the agent. Honor height subject to reserving the agent's minimum usable area; too-small terminals report constrained layout instead of damaging input. Server restart or pane replacement invalidates the backend and requires target revalidation.

Freeze pins a projected revision plus view time; the host continues ingestion/reconciliation. Resume consumes its latest revision. Privacy restriction immediately rebuilds the pinned projection, and frozen age continues to advance. Save/restore terminal state for exit and catchable signals; document `stty sane`/terminal-reset recovery for uncatchable process loss. Overlaying arbitrary native agent TUIs was rejected because input/alternate-screen ownership cannot be guaranteed.

### 11. Configuration and usage providers

Configuration schema v1 is YAML or JSON at an explicit `--config` path or the XDG `openagenthud/config.yaml` location; absence uses defaults and creates no startup files. Never discover repository configuration automatically. Validate complete objects, unknown keys, numeric bounds, field names, provider destinations, and path types. Merge defaults → base file → selected profile → allowlisted `OPENAGENTHUD_*` overrides → CLI flags. Provider execution/network enablement is excluded from environment overrides and requires explicit config/flags. Arrays replace; typed objects merge by declared schema keys. Inspection shows safe origin names, never unrestricted environment dumps.

Validate initial configuration before terminal or child changes. Debounce reloads, validate/compile a whole candidate, then swap one configuration revision; errors retain the last valid revision. Identity-affecting changes retire old source leases and stage a fresh generation, activating target selector and cleared/validated target state coherently. Until activation, an old binding remains labeled as old with a pending target change; privacy restrictions apply immediately even during staging. A confirmed new identity with failed baseline publishes unknown session fields, never relabeled old data. Explicit `config migrate --write` uses a private versioned backup and atomic validated replacement; unknown newer versions fail unchanged. Migration tests use a declared predecessor fixture, not an invented production config.

Usage limits are records keyed by opaque provider/account/window/metric identity. Unit, amount/capacity, observation/reset times, metric kind, currency, and estimate pricing provenance are explicit. Derive percent only from compatible positive capacity. Deadline crossing queues one reconciliation and marks uncertainty; it never resets usage. Local price tables are versioned user inputs with pricing date/source, not automatic internet lookups.

External providers are disabled by default and enabled per provider through explicit argv or HTTPS destination entries. Commands use fixed executable/argument arrays, a documented minimal environment, no shell or telemetry substitution, and owned process groups. Resolve credential references only for a request through private input/explicit provider-specific environment, never argv/state/errors or copied stores. HTTP checks exact scheme/host/port and all IPv4/IPv6 answers on every attempt, pins approved connection addresses to prevent DNS rebinding, and rejects URL userinfo/non-HTTP schemes. Loopback/private/link-local/metadata destinations need explicit trusted-endpoint allowance; loopback HTTP also needs an explicit scheme allowance. Redirects default off; enabled redirects repeat all checks and never forward credentials across origins. A separately configured new-origin query uses its own credential reference. Bound responses/parsing/retries/concurrency, honor cancellation, and publish only validated projected records. HUD-originated requests occur only through enabled usage providers; normal agent requests remain its own behavior.

Automatically evaluating shell strings, fetching prices, rewriting startup files, and silently migrating configuration were rejected because they make an observer unpredictable.

### 12. Acceptance and release evidence

Map every scenario in all nine specs to a test or explicit reproducible smoke procedure and roadmap item. Contract tests exercise the generic adapter and every shipped profile, including additive optional fields, mandatory-feature failures, coverage/keyed updates, and capability withdrawal. Fake clocks replay same-session rebind, selector reload, stamped ingress leases, multi-slice recovery, dependency trust, accounting, and quota deadlines. Controlled traces reject stale/reused approval IDs and unsafe action replay. Security sentinels inspect every sink, including rotated logs, pending exports, unsafe resources, minimal command environments, and DNS/redirect/address checks. Disposable PTY/tmux tests assert terminal restoration, focus, owned cleanup, child survival, resize, and signals. Real provider fixtures plus local smoke records establish compatibility separately from synthetic contract tests.

Performance uses a documented Linux reference environment with at least four CPU cores, 8 GiB RAM, local filesystem, recorded hardware/kernel/runtime/dependency/terminal versions, and one local fixture source. Warm up for five minutes, then measure ten-minute idle and 100-events/s active runs with 1 KiB records and a ten-line 120-column view; include host, view, parser workers, and the controlled client when present, excluding agent/provider processes. Required limits remain ≤1% of one logical core average idle CPU, ≤128 MiB aggregate peak RSS, and ≤250 ms p95 trusted local notification/ingress-to-frame latency. The latter includes debounce/queueing/render batching; provider/remote transport delay is separately reported. Add idle source-read/probe ceilings of ≤16 KiB/s and ≤4 probes/s, with no steady-state full-log rescans. Stable reference recovery with a baseline ≤8 MiB must finish within two reconciliation periods; arbitrary logs instead obey the total recovery ceilings with visible uncertainty. Burst/deep-input runs assert bounded replay/staging, responsive input, and accounting resynchronization. ARM64 performance evidence is native, not emulated. Thresholds are fixed before measurement; a failed budget requires optimization or an explicit evidence-backed plan revision, never an adjustment inside the benchmark.

The CLI declares prelaunch statuses 0 success, 1 operational failure, 2 invalid usage/config/input, 3 unsupported adapter/schema, and 4 unresolved binding. After launch, native/controlled run returns the literal server/child exit result; use documented conventional `128 + signal` mapping when reproducing signal termination is unavailable. Command help/validation have no agent/backend/provider side effects. Bootstrap an aggregate-resource prototype early so the 128 MiB target is assessed before expanding adapter breadth.

CI exposes meaningful commands for typecheck, contract/replay/security, renderer, PTY/tmux integration, and packaging checks. Fast suites need no provider binaries, credentials, or network. Fixture-profile checks and local real-CLI smoke checks separately determine what the compatibility matrix can claim. A release package includes compiled CLI, schemas, examples/templates, license notices, migration/support docs, checksums, and a support matrix. Clean environments exercise generic demo, run/attach, upgrade/rollback and uninstall on both declared architectures. No publication is implicit in creating or applying this change.

Skipping terminal or resource checks because unit tests passed was rejected: the most serious failures occur at process, terminal, recovery, and privacy boundaries.

## Risks / Trade-offs

- [Undocumented provider formats drift] → Gate each source with version/format probes and sanitized local fixtures; disable that source independently and publish verified fallback support.
- [Locally available samples cannot establish all desired fields/modes] → Keep unsupported fields honest and use the generic adapter for common-contract behavior; missing real Codex observer/controlled or Claude mode evidence blocks their completion. Synthetic fixtures are not provider verification.
- [Session evidence remains ambiguous] → Show unresolved selection and require explicit session/launch/pane evidence; never recover by choosing recent files.
- [Delta accounting cannot be reconstructed after loss] → Invalidate totals and require a checkpointed baseline/replay; continue useful independent fields without asserting accurate totals.
- [Privacy restrictions race retained/frozen or pending writes] → Project before all sinks, gate write admission on policy revision, purge rotated logs/staging, test with sentinels, and document that completed user exports cannot be recalled.
- [Native PTY packaging complicates Linux arm64] → Isolate PTY use, test native artifacts in clean environments, and block support claims on failed install/lifecycle checks.
- [Runtime workers and session host add memory/process overhead] → Enforce byte/source limits and measured idle budgets; keep only one current revision plus bounded projected buffers.
- [Minimal controlled client adds control responsibilities] → Keep it explicit, persistent, and separate from observation; block its gate without real protocol evidence and tests for unknown approvals, retired requests, uncertain delivery, cancel/reconnect, and owner loss. Native-TUI parity remains excluded.
- [Large or continuously growing history cannot finish recovery promptly] → Bound fair replay slices/staging/total work, require checkpoints after the ceiling, and restrict convergence deadlines to the declared reference baseline.
- [Private IPC is accessible to other same-user code] → Treat nonces/ownership as session-routing defenses, never as a sandbox; stronger process isolation remains deferred.
- [Terminal Unicode width differs by emulator] → Use tested grapheme width plus a documented override; preserve bounds and ASCII fallback.
- [Uncatchable host loss or tmux server termination damages child I/O] → Separate view lifetime, verify recoverable registry evidence, document terminal recovery, and report host/backend failure honestly without promising survival of the hosting terminal itself.
- [Broad Foundation/MVP/Near-term scope increases delivery time] → Execute dependency-ordered milestones; keep advanced integrations disabled until their own checks pass, and do not mark the change complete at the MVP milestone.

## Migration Plan

1. Build the contract/core/privacy and generic offline slice, followed by deterministic presentation and standalone/tmux lifecycle. Deliver an internal Foundation/MVP milestone with full core recovery/security gates.
2. Add versioned Codex observer and Claude profiles, common accounting/activity, usage providers, fallback profiles, CLI/templates, and the explicit app-server mode with its minimal built-in control client. Enable richer capabilities only after real fixtures, local smoke evidence, and conformance checks pass. Complete all Near-term tasks before considering this change finished; missing required mode evidence remains a blocker.
3. Prepare local release candidates and compatibility documentation for the declared Linux architectures/runtime/backend. Run clean install, demo, run/attach, upgrade/migration, rollback, uninstall, terminal and resource gates. Publication requires a separate explicit release action.
4. First-install configuration absence uses defaults. Explicit migrations produce a versioned backup and atomically replace only HUD configuration; agent stores, database files, shell startup files, and unrelated tmux resources are never migrated.
5. Roll back a failed candidate by stopping the HUD view, disabling the failing adapter/profile/provider, restoring the prior package and backed-up configuration, and reconnecting to the surviving session host when compatible. If the host protocol is incompatible, stop observation without killing the child and attach with the supported observer mode. Unknown configuration majors fail with migration guidance.
6. Uninstall removes the package, explicitly installed wrapper/template references, and owned expired HUD runtime/cache files. It does not terminate an active launched agent or delete provider history. An active run host removes its remaining runtime registry when its child exits.

No open questions are required to start implementation. The exact verified provider-version entries, fixture inventory, terminal-width overrides, and measured reference-system results are outputs of specified validation tasks; they cannot relax the contracts or substitute guesses for compatibility evidence.
