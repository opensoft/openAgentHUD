## Concrete strengths

- **Useful contract precision.** Sol specifies snapshot coverage, atomic capability withdrawal, independent disclosure/availability, and immutable revisions in [normalized-agent-state](../agent-hud-platform-sol/specs/normalized-agent-state/spec.md). Its [design decisions 2–5](../agent-hud-platform-sol/design.md#2-versioned-values-plus-metadata-with-explicit-update-coverage) add path validation, read-start guards, cumulative checkpoints, and deduplication watermarks. These improve the roadmap's omission/clear, ordering, and accounting guarantees; Astra previously left several of them implicit.
- **Privacy includes retained state.** [Configuration privacy](../agent-hud-platform-sol/specs/configuration-privacy/spec.md) covers frozen views, provenance, unclassified extensions, and non-resurrection after policy relaxation. The count/byte/age retention limits in design decision 3 are stronger than Astra's original count/age-only history budget.
- **Actionable user workflows.** [CLI](../agent-hud-platform-sol/specs/hud-cli/spec.md) defines clean JSON stdout and instance-targeted view actions. [Adapter integration](../agent-hud-platform-sol/specs/adapter-integrations/spec.md) requires preserving existing Claude status-line behavior. These are concrete acceptance criteria beyond simply listing commands and templates.
- **Honest delivery and ownership.** [Proposal](../agent-hud-platform-sol/proposal.md) explicitly includes Near-term work before full completion. Design decisions 9 and 12 separate view/host lifetimes, distinguish synthetic contract fixtures from provider evidence, and declare a finite native platform matrix. Keeping packaging and publication separate is also clearer than Astra's original migration wording.

## Findings and better alternatives

1. **High — launch authentication cannot prove current-session identity.** [Design decision 9](../agent-hud-platform-sol/design.md#9-session-host-ingress-and-controlled-transport) gives producers the current generation after authentication; decision 8 describes hooks inheriting launch correlation. An old hook reconnecting after rollover can still hold that launch credential. The wrong-generation scenario in the adapter spec tests a supplied mismatch, not old data receiving a new generation. Require current session/source evidence before issuing a generation/epoch lease, retire leases on rollover, and test this reconnect race. Astra's original ingress stamping had the same gap; it is now corrected.

2. **High — controlled-mode usability lacks a concrete completion gate.** Sol requires an explicitly supplied relay-compatible client but establishes no usable client/version. [Tasks 15.1–15.4](../agent-hud-platform-sol/tasks.md#15-explicit-controlled-mode-and-integration-templates) primarily verify protocol fixtures and a local fixture client/server; task 11.1 also permits missing provider evidence to remain unsupported. Safe fallback is appropriate at runtime, but must not count as delivering the proposal's mandatory modes. Require an actual usable client/server smoke check and explicit incomplete status without it. Astra adopts transport/telemetry isolation, retains its bounded bundled control surface, and strengthens the real-provider gate rather than importing an unproven external-client dependency.

3. **Medium — accounting design is stronger than its acceptance cases.** Sol's design decision 5 explains baseline checkpoints and ID eviction, while [agent-telemetry](../agent-hud-platform-sol/specs/agent-telemetry/spec.md) and [session-synchronization](../agent-hud-platform-sol/specs/session-synchronization/spec.md) mostly test duplicate/reset/gap cases. Add baseline 100 through sequence 20, replayed 19, and delta 5 at 21 → 105 after ID eviction; test unknown cross-epoch overlap and a later-started read containing old data. These make the roadmap's accounting and stale-read guarantees executable rather than relying on design prose.

4. **Medium — summary consent is ambiguous across artifacts.** Agent-telemetry's “Plans goals summaries” requirement and task 13.4 require explicit content and retention settings; design decision 3 treats display and retention as separate permissions. It is unclear whether display with retention off is valid. Add a display-only scenario, allow only the current permitted summary, and forbid implicit summarization requests. Astra keeps that explicit behavior and adopts Sol's no-resurrection rule for all frozen/retained content.

5. **Medium — resource evidence is incomplete.** [Platform verification](../agent-hud-platform-sol/specs/platform-verification/spec.md) fixes CPU/RSS/latency and queue limits but only publishes source-I/O cadence, without a pass/fail I/O budget required by the roadmap. Its idle benchmark scenario also asks for latency; an idle source provides no event samples. Design decision 12's separate active trace is the better formulation. Astra keeps numeric I/O/probe limits, specifies active record sizes and aggregate owned-process costs, adds global query/history byte bounds, and limits its own previously unconditional recovery deadline to a declared workload envelope.

6. **Medium — survival guarantees need consistent boundaries.** [Terminal presentation](../agent-hud-platform-sol/specs/terminal-presentation/spec.md) broadly says HUD failure cannot terminate/corrupt the agent; design decision 9 explicitly excludes host failure and whole-tmux-server loss. Tests exercise view loss. State the guaranteed view-failure behavior and hosting-failure limitation together. Sol's migration plan correctly preserves active hosts on uninstall; Astra adopts that safeguard for rollback too, replacing its own overly broad “stop owned workers/endpoints” instruction.

## Reconciliation in Astra

The revised [design](design.md) and [tasks](tasks.md) carry these decisions into all nine existing capabilities: atomic contract changes and checkpoint accounting; epoch/lease isolation; explicit privacy dimensions and profile precedence; safe summary/quota derivation; hook preservation and control-plane isolation; targeted CLI actions; bounded retention/query work; and native, evidence-backed release gates. New scenarios cover the identified races and negative cases.

Retained deliberately: Astra's keyed collection operations, JSON-only configuration, Linux x86_64/macOS arm64 targets, and bounded bundled control client. Sol's alternative library stack, Linux-only matrix, and external-client assumption are not correctness requirements. Both plans remain large Foundation/MVP/Near-term programs; stage gates organize delivery but do not justify silently dropping mandatory integration evidence or implementing Later features.
